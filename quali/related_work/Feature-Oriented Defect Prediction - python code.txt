2 - as caracteristicas de features defeituosoas são uteis para a descobertas de features que

avaliando 7 classifiers com 3 diferentes conjuntos de atributos 

Intro
neste trabalho é apresetada uma investigação sobre predição orientada a feature. Predizendo erros
baseando-se na granularidade das features. As features sao importantes unidades de abstração e 
também são iportantes para o desenvolvimento agil no momento do planejamento de sprints e organização 
de processos pois são planejados baseados nas requisições de features. 

Predição de defeitos a nivel de feature se torna promissor por cona de que algumas features podem 
ser mais propensas a erros, avaliando o historico dos projetos e de outros projetos parecidos.
Algumas features podem ser mais ou menos propensas a erros dadas algumas caracteristicas que podem 
ser aproveitadas na predição. 
Por fim, features que possuem códigos muito especificos podem ter maior propensao a erros do que as demais.

Este artigo tem as contribuições:

- um dataset orientado a feature contendo 122 projetos que ja foram usados para pesquisas orientadas a feature

- introdução de duas metricas para o treinamento de classificadores para a predição orientada a feature. Uma
delas sendo um conjunto de metricas em oito processos baseados em feature e o segundo conjunto tem seis metricas de estrutura

- avaliação da predição de defeitos orientada a features baseada no dataset em 3 conjuntos de metricas,
um existente e dois adicionados e sete classificadores.

Metodologia
1 - criar o dataset de features com rolutos ao longo do historico de desenvolvimento dos projetos
Cada instancia do dataset é uma feature. Para isso utilizaram projetos que tem historias de revisao
e usaram macros (#ifdef) para fazer anotação de codigos com features. Por meio de diff de commits eles
coletaram com preprocesssor  #ifdef and #ifndef.
para identificar commits de bug fix, eles usaram heuristica de keywords, refinando para minimizar falsos positivos
Assim, foi possivel usar os commits de correção para identificar os commits introdutores dos bugs 
usando SZZ algoritmo que usa as linhas modificadas para detectar o que foi ajustado e em qual 
commit foi introduzida

Jacek Śliwerski, Thomas Zimmermann, and Andreas Zeller. 2005. When do
changes induce fixes? ACM SIGSOFT Software Engineering Notes 30, 4 (July 2005),
1
Davide Spadini, Maurício Aniche, and Alberto Bacchelli. 2018. PyDriller: Python
framework for mining software repositories. In ESEC/FSE. ACM Press, 908–911

2 - crias os dois novos conjuntos de metricas (feature engineering) sendo que as metricas
sao atributos

3 - selecionar e treinar com 7 tipos de classificadores 
Foram selecionados utilizando estudos anteriores -  J48 (Decision Tree),
LR (Regression), NB (Bayesian),  k-Nearest Neighbor (KNN)

Para testar e treinar as redes foi utilizado o weka (arquivo .arff) (que ja tem os algoritmos e ferramentas
de pre processamento)
